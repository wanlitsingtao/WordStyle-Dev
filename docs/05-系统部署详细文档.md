## 3. Supabase数据库配置

### 3.1 创建Supabase项目

1. 登录 [Supabase](https://supabase.com)
2. 点击 "New Project"
3. 填写项目信息:
   - Name: wordstyle
   - Database Password: 设置强密码
   - Region: 选择靠近用户的区域(如Singapore)
4. 等待项目创建完成(约2分钟)

### 3.2 获取数据库连接信息

1. 进入项目 → Settings → Database
2. 找到 "Connection string" 部分
3. 复制以下两种连接字符串:

**直连地址(Session mode)**:
```
postgresql://postgres:[YOUR-PASSWORD]@db.{project_id}.supabase.co:5432/postgres
```

**连接池器地址(Transaction mode)**:
```
postgresql://postgres.{project_id}:[YOUR-PASSWORD]@aws-{region}.pooler.supabase.com:6543/postgres
```

**重要**: 
- **Render部署必须使用连接池器地址**(端口6543)
- 用户名格式为 `postgres.{project_id}` (带项目ID)
- 主机名格式为 `aws-{region}.pooler.supabase.com`

### 3.3 执行数据库迁移

#### 方法1: 通过Render自动执行(推荐)

Render启动时会自动执行`alembic upgrade head`,无需手动操作。

#### 方法2: 本地手动执行

```bash
cd backend

# 设置环境变量
export DATABASE_URL="postgresql://postgres.{project_id}:密码@aws-{region}.pooler.supabase.com:6543/postgres"

# 执行迁移
alembic upgrade head
```

### 3.4 验证数据库表

连接数据库后,确认以下表已创建:
- `users`: 用户信息表
- `conversion_tasks`: 转换任务表
- `system_config`: 系统配置表
- `comments`: 评论表
- `feedbacks`: 反馈表
- `style_mappings`: 样式映射表

## 5. Streamlit Cloud前端部署

### 5.1 创建Streamlit App

1. 登录 [Streamlit Cloud](https://streamlit.io/cloud)
2. 点击 "New app"
3. 配置应用:
   - **Repository**: wanlitsingtao/WordStyle
   - **Branch**: main
   - **Main file path**: app.py
   - **App name**: wordstyle

### 5.2 配置Secrets

在Streamlit Cloud控制台 → Settings → Secrets 中添加:

```toml
# Streamlit Cloud 配置（API模式）
# 注意：同时配置 BACKEND_URL 和 USE_SUPABASE=true 时，会自动检测为 API 模式
BACKEND_URL = "https://wordstyle-backend.onrender.com"
USE_SUPABASE = true  # 启用数据库功能（非本地SQLite）

# DATABASE_URL 在 API 模式下不需要，但保留用于切换模式
DATABASE_URL = "postgresql://postgres.{project_id}:密码@aws-{region}.pooler.supabase.com:6543/postgres"
```

**数据源模式自动检测逻辑**：
- **API模式**：BACKEND_URL存在 + USE_SUPABASE=true → 通过后端API访问数据库（Streamlit Cloud）
- **Supabase直连模式**：DATABASE_URL存在 + USE_SUPABASE=true + 无BACKEND_URL → 直接连接数据库（Render后端）
- **Local模式**：USE_SUPABASE=false 或无数据库配置 → 使用本地SQLite + JSON文件（本地开发）

**注意**: 
- BACKEND_URL必须指向Render部署的后端API
- USE_SUPABASE设置为true启用数据库功能
- **仅当 `BACKEND_URL` 非空**时才会检测为 API 模式；若该变量存在但为空，会落入 **Supabase 直连模式**（当前线上即为此种配置，见 `03-Bug修复记录文档.md` 2026-09-15 记录）
- 转换结果与临时文件落在**运行进程的本地磁盘**（`temp/`、`temp/conversion_results/`），与数据源模式无关；部署时需保证该目录可写，且实例不要被回收式重建

## 9. 故障排查指南

### 9.1 Render部署失败

#### 问题1: Build失败

**症状**: 部署日志显示pip install错误

**原因**: 
- requirements.txt缺失或格式错误
- 依赖包版本冲突

**解决**:
```bash
# 检查requirements.txt
cat backend/requirements.txt

# 重新生成依赖文件
pip freeze > backend/requirements.txt
```

#### 问题2: Start Command未执行Alembic迁移

**症状**: 日志显示直接启动Uvicorn,没有Alembic输出

**原因**: Render缓存了旧的render.yaml配置

**解决**:
1. 在Render控制台 → Settings
2. 找到 "Start Command"
3. 手动修改为: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
4. 保存并触发重新部署

#### 问题3: ModuleNotFoundError: No module named 'app'

**症状**: Alembic迁移失败,提示找不到app模块

**原因**: alembic/env.py未正确设置sys.path

**解决**: 确认`backend/alembic/env.py`开头包含:
```python
import sys
import os
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
```

### 9.2 数据库连接失败

#### 问题1: could not translate host name

**症状**: DNS解析失败

**原因**: 
- 使用了错误的连接池器地址
- 用户名格式错误

**解决**:
- 确认使用Supabase提供的标准连接池器地址
- 用户名格式: `postgres.{project_id}`
- 主机名: `aws-{region}.pooler.supabase.com`
- 端口: `6543`

#### 问题2: Network is unreachable

**症状**: IPv6连接失败

**原因**: 尝试通过IPv6连接Supabase直连地址

**解决**: 改用连接池器地址(端口6543)

#### 问题3: invalid interpolation syntax

**症状**: Alembic解析DATABASE_URL失败

**原因**: URL中的`%`被configparser误解析

**解决**: 确认`backend/alembic/env.py`中转义百分号:
```python
escaped_url = database_url.replace('%', '%%')
config.set_main_option("sqlalchemy.url", escaped_url)
```

### 9.3 前端无法连接后端

#### 问题1: CORS错误

**症状**: 浏览器控制台显示CORS policy错误

**原因**: ALLOWED_ORIGINS配置错误

**解决**: 
- 确认Render环境变量ALLOWED_ORIGINS设置为`https://*.streamlit.app`
- 重启Render服务

#### 问题2: API返回404

**症状**: 前端调用API返回404

**原因**: BACKEND_URL配置错误

**解决**:
- 检查Streamlit Secrets中BACKEND_URL是否正确
- 确认后端服务正常运行: `curl https://wordstyle-backend.onrender.com/health`

### 9.4 用户数据无法写入

#### 问题1: 用户ID类型不匹配

**症状**: SQL错误,提示类型不匹配

**原因**: users表的id字段类型不是VARCHAR(12)

**解决**:
```sql
-- 检查表结构
\d users

-- 如果类型错误,执行迁移修正
alembic upgrade head
```

#### 问题2: 外键约束失败

**症状**: 插入数据时外键约束错误

**原因**: 引用了不存在的用户ID

**解决**: 确认先创建用户,再创建关联记录

## 11. 常见问题FAQ

### Q1: 为什么使用连接池器而不是直连?

**A**: Render的网络环境无法通过IPv6连接Supabase直连地址,而连接池器使用IPv4,兼容性更好。此外,连接池器可以更好地管理数据库连接,提高性能。

### Q2: 免费套餐的限制是什么?

**A**: 
- **Render**: 每月750小时免费时长,服务休眠后首次访问需等待30秒唤醒
- **Streamlit Cloud**: 完全免费,无限制
- **Supabase**: 500MB数据库存储,每月2GB带宽

### Q3: 如何升级到付费套餐?

**A**: 
- **Render**: 控制台 → Settings → Upgrade Plan
- **Supabase**: 控制台 → Settings → Billing → Upgrade

### Q4: 服务休眠后会影响用户体验吗?

**A**: Render免费套餐的服务在15分钟无访问后会休眠,下次访问需等待30秒唤醒。建议:
- 使用uptime监控服务保持活跃
- 或升级到付费套餐禁用休眠

### Q5: 如何回滚到之前的版本?

**A**: 
1. 在GitHub上revert commit
2. 推送后Render自动重新部署
3. 或在Render控制台手动选择之前的部署版本

## 13. 本地开发版 → 云端发布版 同步边界

### 13.1 两个工作副本

| 目录 | 角色 | 谁改 |
|---|---|---|
| `bid-buddy-dev` | 本地开发版，**所有代码改动只在这里做** | 开发（含 AI 协助） |
| `bid-buddy-pub` | 云端发布版，在 Streamlit Cloud 上运行 | **只由人工同步，AI 不代劳** |

### 13.2 同步脚本

`sync_bid_buddy_dev_to_bid_buddy.bat`（位于两个目录的上一级），1 步快照 + 6 步 robocopy + 1 步检查：

| 步骤 | 源 → 目标 | 关键排除 |
|---|---|---|
| [0/6] | 同步**前**快照 `pub\config.py` 的原状（大小 / 时间 / 是否与 dev 不同） | 只读，绝不复制 |
| [1/6] | 根 `*.py` → 根 | `/XD .git .venv .venv-validation __pycache__ conversion_results data desk test` |
| [2/6] | `components` → `components` | `*.pyc *.log *.db *.json .env*` |
| [3/6] | `views` → `views` | 同上 |
| [4/6] | `backend\app` → `backend\app` | 同上 |
| [5/6] | `.streamlit\config.toml` → 同路径 | `secrets.toml` 保持本地，**不同步** |
| [6/6] | `resource` → `resource` | `*.log *.db *.json .env*` |
| **[check]** | 三个 `config.py` 同步**后**断言 | **只读**；先报告本次是否覆盖了 pub 旧版（被覆盖时打印原大小/时间 + `git` 回退命令），再逐一断言 `config.py`、`backend\app\config.py`、`backend\app\core\config.py` 两侧一致 |

`config.py` 自 2026-09-15 起**纳入自动同步**（依据见 13.3），不再有任何 `config.py` 排除项。

每一步都带 `if exist` 源目录存在性保护（缺目录只打印 `[SKIP]`、不中止）
与 `if errorlevel 8 goto :failed` 失败即中止。`[check]` 步只读不写，不会改变退出码。

### 13.3 `config.py` 为什么可以自动同步（2026-09-15 结论）

旧版脚本把 `config.py` 永久排除（`/XF config.py`），理由是注释里的
"config.py is environment-specific and is excluded"。**逐项审计后，这条理由对现在的文件不成立。**

**一、根 `config.py` 的 40 个配置项，逐项判定后没有一项是环境专属的：**

| 类别 | 项数 | 说明 |
|---|---|---|
| 路径类 | 8 | 全部由 `__file__` 派生（`BASE_DIR`/`TEMP_DIR`/`DATA_DIR`/`RESULTS_DIR`/`USER_DATA_FILE`/`COMMENTS_FILE`/`TASKS_DB_FILE`/`LOG_FILE`）——每个副本自动解析到自己所在目录，覆盖不会串味 |
| 运行时注入 | 7 | `USE_SUPABASE`/`DATABASE_URL`/`BACKEND_URL`/`DATA_SOURCE`/`ADMIN_CONTACT`/`LOG_LEVEL` 走 `st.secrets` → `os.getenv` → 默认值，**文件里没有任何具体值** |
| 业务常量 | 27 | 价格、免费额度、充值档位、样式映射、应答句、阈值、UI 文案——与环境无关，而且**必须**两侧一致（否则计费与免费额度会不一致） |

**二、真正个性化的东西不在 `config.py` 里，而且早已被排除**：`.streamlit\secrets.toml`
（dev 154 字节 / pub 755 字节，内容确实不同）、`.env`、`data\`、`conversion_results\`——
同步脚本对它们都有排除规则（或根本不在复制范围内：第 [1/6] 步只取 `*.py`），永不触碰。

**三、git 历史佐证**：dev 侧 `config.py` 有 11 个版本、pub 侧 19 个，**没有任何一版出现过
真实密钥、真实磁盘路径或真实域名**；正则命中的全是文档字符串里的示例
（`https://xxx.supabase.co`）与占位符（`your_wechat_id`）。历史上唯一一次真正环境专属的值是
2026-05 的 `BACKEND_URL` 默认值 `http://localhost:8000`，**该默认值早已删除**
（现在是 `os.getenv("BACKEND_URL")` → `None`）。

**四、"environment-specific" 这条理由的来源**：2026-05-11 前后，pub 侧 `config.py` 连续多次
单独提交，专门修 Streamlit Cloud 的 secrets 读取、pooler 连接串转换、布尔值解析等问题。
**这些修复后来全部并入 dev，两侧已收敛**，排除条款遂成遗留保险。而且它其实挡不住人——
pub 2026-09-08 的 `e001a50 同步dev全部改进` 就把 `config.py` 一起提交了；
排除只挡住了 robocopy，没挡住手工复制，结果是「有时记得、有时忘」。

**结论**：三个 `config.py`（根、`backend\app\config.py`、`backend\app\core\config.py`）
全部纳入自动同步，规则简化为「**源码即通用，差异走运行时注入**」。

> **必须守住的一条分界线**
> 需要按环境取不同值的配置，**一律放进 `.streamlit\secrets.toml` 或环境变量**，绝不 fork 源文件。
> 一旦某个值被硬编码进 `config.py` 且两侧要求不同，下次同步就会把它冲掉——
> 届时 `[check]` 步会报告被覆盖的旧内容并给出回退命令，但更好的做法是根本不这么做。

这条分界线也是 `backend\app\core\config.py` 的现状：`DEBUG`、`SECRET_KEY`、`ALLOWED_ORIGINS`
都留了占位默认值，真实值由 pydantic `BaseSettings` 从环境变量读取（Render 侧用控制台环境变量
覆盖），所以两侧文件可以是逐字节相同的。

**事故记录（本次取消排除的直接动因）**：2026-09-15 当天 5 个文件的修复中 4 个同步成功，
只有 `config.py` 被挡在第 [1/6] 步之外，停在 `2026-09-08 11:56` 版本，导致 pub 的
`RESULTS_DIR` 仍指向项目根 `conversion_results/`，与 dev（`temp/conversion_results/`）
及文档口径不一致。详见 `docs/03-Bug修复记录文档.md`。

### 13.4 执行约定

- 同步动作**由人工执行**（双击脚本）；AI 不代劳、不 `git push`、不自动 commit。
- 脚本输出的文件列表就是**本次真正复制/更新**的内容；两侧完全一致的文件
  会被 robocopy 静默跳过（不打印），"[SKIP]" 表示源目录不存在（不是错误）。
- 根 `config.py` 被覆盖时，`[check]` 步会明确打印
  `[INFO] pub\config.py differed before this run and has been OVERWRITTEN`
  + 被覆盖内容的原大小与时间，并给出回退命令。**想先看差异再决定**，可执行：

  ```bat
  fc /L /N "E:\LingMa\WordStyle\bid-buddy-dev\config.py" "E:\LingMa\WordStyle\bid-buddy-pub\config.py"
  ```

- pub 若被单独改动过，两侧都是 git 仓库，回退代价很低：

  ```bat
  git -C "E:\LingMa\WordStyle\bid-buddy-pub" diff  -- config.py
  git -C "E:\LingMa\WordStyle\bid-buddy-pub" checkout -- config.py
  ```
